# RL29 fork of Akkudoktor-EOS

This repository is a private fork of [Akkudoktor-EOS/EOS](https://github.com/Akkudoktor-EOS/EOS)
for the installation at example.org. It runs as a Docker container in the Portainer stack `eos`
on the VM "energy" (eos.local) and is controlled by Home Assistant.

The fork exists to add a native heat pump / hot water / heating rod model to the GENETIC
optimizer, plus a few fixes the installation needs. Everything else follows upstream.

## Branches

| Branch | Purpose |
| --- | --- |
| `main` | Mirror of upstream `main`, never committed to directly |
| `rl29/main` | Upstream base commit + fork commits; every push builds the image |
| `rl29/feat-*` | Work in progress, merged into `rl29/main` after tests pass |

Base commit of the current `rl29/main`: see `git merge-base rl29/main upstream/main`.

## Fork-specific files

Kept outside upstream files wherever possible so that rebasing stays conflict free:

- `.github/workflows/rl29-image.yml` — tests, image build, smoke test, push to GHCR
- `scripts/rl29/smoke_test_image.sh` — starts an image and checks health, config, providers
- `scripts/rl29/eos_snapshot.py` — snapshot/diff of a running EOS (acceptance check)
- `scripts/rl29/calibrate_heatpump.py` — fits building (with solar aperture), COP scale and tank loss from HA history,
  for a first calibration; the same fits run automatically in EOS (`devices.heat_pumps.<id>.calibration`)
- `scripts/rl29/compare_heatpump_plan.py` — plan vs. actual (room temperature, heat pump energy per mode)
- `scripts/rl29/check_heatpump_plan.py` — plausibility check of the heat pump plan (hourly during commissioning)
- `scripts/rl29/gridfee_14a.py` — §14a grid fee module snippet (none, module1, module2, module1_3)
- `tests/rl29/` — fork tests, including the production configuration of the energy VM
- `RL29.md` — this file
- `RL29-HEATPUMP.md` — heat pump commissioning: EOS config, HA dispatcher draft, stack change
- `RL29-APPLIANCES.md` — request-driven appliances (washing machine): EOS config and HA control

Fork code inside upstream modules (kept small, marked "RL29 fork"):

- `devices/thermal/` (building, tank, COP, heat pump system, `calibration.py` fits) and
  `devices/settings/heatpumpsettings.py`; `devices/heatpumpcalibration.py` runs the fits inside EOS,
  `devices/heatpumpplanactual.py` compares the recorded plans with the measurements
- `devices/applianceprofiles.py` — learned load profiles of home appliances per program
- `optimization/genetic/heatpumpgenes.py` — heat pump genes; hooks in `genetic.py`,
  `geneticparams.py`, `geneticsolution.py`, `configrequest.py`
- `config/configabc.py` — `TimeWindow.months`, DST-safe window bounds
- `adapter/homeassistant.py` — direct HA connection without Supervisor
- `prediction/gridcontrol14a.py` — §14a modules; module 3 in `elecfeefixed.py`, module 2 and dimming for heat pumps
- `prediction/pvforecastpvlib.py` — loss and inverter limits applied

## Testing

Every change is tested before it reaches `rl29/main`:

```bash
uv sync --extra dev
uv run pytest -q tests/rl29                                   # fork tests (fast)
uv run pytest --finalize --check-config-side-effect -q        # full upstream suite (CI)
```

The CI workflow runs both, then builds the image and smoke-tests the published digest.

Local smoke test of any image:

```bash
bash scripts/rl29/smoke_test_image.sh ghcr.io/quidong/eos:rl29-latest
```

## Release / deploy

1. Push to `rl29/main` → workflow `rl29-image` publishes `ghcr.io/quidong/eos:rl29-<sha>`
   and `:rl29-latest`; the job summary shows the digest.
2. Snapshot the running EOS: `python3 scripts/rl29/eos_snapshot.py snapshot http://eos.local:8503 -o before.json`
3. Back up `/data/config/EOS.config.json` (Portainer exec or `GET /v1/config/backup`).
4. Replace the `image:` line of the `eos` service in the Portainer stack with
   `ghcr.io/quidong/eos@sha256:<digest>` and redeploy.
5. Snapshot again and compare: `python3 scripts/rl29/eos_snapshot.py diff before.json after.json`.

Rollback: put the previous digest back into the stack and restore the saved configuration.
A rollback to an upstream image fails once the configuration contains fork-only keys
(e.g. `devices.heat_pumps`), so always restore the backup that matches the image.

Watchtower must not update this container; the image carries the label
`com.centurylinklabs.watchtower.enable=false`.

## Rebasing onto upstream

```bash
git fetch upstream
git checkout rl29/main
git rebase <new-upstream-commit>        # pick a commit whose upstream CI is green
uv run pytest -q tests/rl29 && uv run pytest --finalize --check-config-side-effect -q
git push --force-with-lease origin rl29/main
```

Rebase when a security fix or a wanted feature lands, otherwise about monthly.
